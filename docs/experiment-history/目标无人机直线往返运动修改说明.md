## 1. 修改背景和最终目标

开始本次修改前，已经完成了两项实验参数调整：

1. 在启动命令中把拦截无人机速度设为 `4 m/s`；
2. 把相机频率和比例导引相关更新频率统一为 `60 Hz`。

本文件只记录这之后进行的“目标无人机直线运动”修改。最终需求是：

- 目标机不再默认做圆周运动，而是在有限的直线上往返；
- 两端点总间距为 `20 m`，避免目标机一直直飞并离开实验区域；
- 最大速度为 `3 m/s`；
- 到达端点前先减速到零，再平滑反向加速，不瞬间改变速度方向；
- 目标机的机头朝向固定，不在端点掉头；
- 目标机起飞并在路径中心稳定后，才开始直线运动；
- 直线方向应当在拦截机相机中表现为横向经过，而不是朝相机前后运动；
- 保留原来的 `circle`、`sinusoidal`、`random_walk` 模式，必要时可以通过参数切回。

最终默认参数如下：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `motion_mode` | `linear` | 默认使用直线往返模式 |
| `linear_path_length` | `20.0 m` | 两端点之间的总长度 |
| `linear_max_speed` | `3.0 m/s` | 目标机的规划最大速度 |
| `linear_acceleration` | `2.0 m/s²` | 加速和制动的加速度绝对值 |
| `staging_position_tolerance` | `0.35 m` | 起飞稳定判定允许的三维位置误差 |
| `staging_velocity_tolerance` | `0.25 m/s` | 起飞稳定判定允许的三维速度 |
| `staging_stable_duration` | `1.0 s` | 必须连续满足稳定条件的时间 |

目标机轨迹控制定时器仍为原来的 `10 Hz`（周期 `0.1 s`）。这和相机、图像处理及比例导引的 `60 Hz` 是不同的控制环节，本次没有把目标机轨迹定时器改成 `60 Hz`。

## 3. 头文件中的改动

文件：

```text
uav_target_sim/include/uav_target_sim/uav_target_sim.hpp
```

### 3.1 增加本地位置消息

加入：

```cpp
#include <px4_msgs/msg/vehicle_local_position.hpp>
```

对应增加订阅对象：

```cpp
rclcpp::Subscription<VehicleLocalPosition>::SharedPtr local_position_sub_;
```

作用：读取 PX4 对目标机自身位置和速度的真实估计值。没有这个反馈，只能知道“给目标机下了什么指令”，无法判断它是否已经真正到达起飞位置并稳定。

### 3.2 增加直线运动模式

原有枚举前增加：

```cpp
LINEAR,  // 有限直线平滑往返
```

并把默认模式改为：

```cpp
MotionMode motion_mode_ = MotionMode::LINEAR;
```

原有的圆周、正弦和随机游走模式没有删除。

### 3.3 增加直线轨迹参数和状态变量

主要成员变量如下：

```cpp
float linear_path_length_ = 20.0f;
float linear_half_length_ = 10.0f;
float linear_max_speed_ = 3.0f;
float linear_acceleration_ = 2.0f;
float linear_center_x_ = 0.0f;
float linear_center_y_ = 0.0f;

float linear_position_ = 0.0f;
float linear_velocity_ = 0.0f;
float linear_acceleration_cmd_ = 0.0f;
float linear_leg_start_ = 0.0f;
float linear_leg_end_ = 10.0f;
float linear_leg_elapsed_ = 0.0f;
```

含义：

- `linear_path_length_` 是两个端点的总距离；
- `linear_half_length_` 是中心到任一端点的距离，等于总长度的一半；
- `linear_position_` 是目标机相对于路径中心的位置；
- `linear_velocity_` 和 `linear_acceleration_cmd_` 是当前要发布的速度、加速度；
- `linear_leg_start_`、`linear_leg_end_` 表示当前这一段从哪里飞到哪里；
- `linear_leg_elapsed_` 记录当前单程已经运行多久。

默认情况下，路径中心为 `(0, 0)`，两端点在 PX4 局部 NED 坐标中是：

```text
(-10, 0, -5)  <----  (0, 0, -5)  ---->  (10, 0, -5)
```

目标机刚开始运动时先从中心飞向 `+10 m`，之后再在 `+10 m` 和 `-10 m` 之间完整往返。

### 3.4 增加起飞稳定判定状态

增加：

```cpp
float staging_position_tolerance_ = 0.35f;
float staging_velocity_tolerance_ = 0.25f;
float staging_stable_duration_ = 1.0f;
int staging_stable_ticks_ = 0;
bool motion_started_ = false;
```

同时保存目标机的实际位置和速度：

```cpp
float local_x_, local_y_, local_z_;
float local_vx_, local_vy_, local_vz_;
bool local_position_valid_ = false;
```

这些变量用于实现“先起飞并稳定，再开始运动”。只要位置或速度有一次超出阈值，连续稳定计数就会清零，必须重新连续满足 `1 s`。

### 3.5 扩展轨迹发布函数

原函数只接收位置：

```cpp
void publish_trajectory_setpoint(float x, float y, float z);
```

现在可以同时接收位置、速度和加速度：

```cpp
void publish_trajectory_setpoint(
    float x, float y, float z,
    float vx = 0.0f, float vy = 0.0f, float vz = 0.0f,
    float ax = 0.0f, float ay = 0.0f, float az = 0.0f);
```

默认参数都为零，所以原有的圆周等模式只传位置时仍可继续工作。

## 4. C++ 实现中的改动

文件：

```text
uav_target_sim/src/uav_target_sim.cpp
```

### 4.1 声明并读取 ROS 2 参数

新增参数：

```cpp
this->declare_parameter<std::string>("motion_mode", "linear");
this->declare_parameter<double>("linear_path_length", 20.0);
this->declare_parameter<double>("linear_max_speed", 3.0);
this->declare_parameter<double>("linear_acceleration", 2.0);
this->declare_parameter<double>("staging_position_tolerance", 0.35);
this->declare_parameter<double>("staging_velocity_tolerance", 0.25);
this->declare_parameter<double>("staging_stable_duration", 1.0);
```

参数读取后使用 `std::max` 设置下限，防止出现零长度、零速度、零加速度或不合理的负值。例如：

```cpp
linear_max_speed_ = std::max(0.1f, ...);
linear_acceleration_ = std::max(0.1f, ...);
```

如果输入了无法识别的 `motion_mode`，现在会警告并退回 `linear`，而不是退回 `circle`。

### 4.2 订阅目标机本地位置和速度

订阅的话题是：

```text
/px4_2/fmu/out/vehicle_local_position
```

回调函数保存：

- `x、y、z`：目标机在 PX4 局部 NED 坐标中的实际位置；
- `vx、vy、vz`：目标机的实际速度；
- `xy_valid、z_valid、v_xy_valid、v_z_valid`：位置和速度估计是否有效。

只有这些有效标志全部为真，稳定判定才会继续计数。

### 4.3 起飞、就位和延迟开始运动

启动节点后，程序仍然先连续发送一批 Offboard 设定点，再切换 Offboard 并解锁。预发送和等待稳定阶段的目标位置统一为：

```cpp
(linear_center_x_, linear_center_y_, pos_z_)
```

默认就是 PX4 NED 坐标 `(0, 0, -5)`，即在路径中心悬停，高度约为 `5 m`。

解锁后并不立即开始横向运动，而是持续发布中心悬停点，并检查：

```text
三维位置误差 <= 0.35 m
三维速度大小 <= 0.25 m/s
连续满足时间 >= 1.0 s
```

三维位置误差和速度大小使用欧氏距离：

```text
position_error = sqrt(dx² + dy² + dz²)
speed          = sqrt(vx² + vy² + vz²)
```

轨迹定时器周期为 `0.1 s`，所以默认要求连续满足约 `10` 个控制周期。满足后日志会出现：

```text
Target stable; starting motion with fixed yaw=0
```

### 4.4 固定目标机朝向

每次发布 `TrajectorySetpoint` 时都设置：

```cpp
msg.yaw = 0.0f;
msg.yawspeed = 0.0f;
```

因此目标机在端点不会转动 `180°`。多旋翼不需要把机头对准速度方向，它可以在固定朝向下侧飞或倒飞。

这里的“固定”指固定在 PX4 局部 NED 坐标系的 `yaw = 0`，并不是“始终朝向拦截机”。

### 4.5 端点平滑反向：梯形/三角速度曲线

直线单程不是在端点突然把速度从 `+3 m/s` 改成 `-3 m/s`，而是按以下过程运行：

```text
加速 -> 匀速 -> 减速到 0 -> 下一段反向加速
```

设单程距离为 `D`，最大速度为 `vmax`，加速度绝对值为 `a`：

```text
加速时间 ta = vmax / a
加速距离 da = 0.5 × a × ta²
```

如果 `2 × da <= D`，有足够距离达到最大速度，使用梯形速度曲线；如果 `2 × da > D`，来不及达到最大速度，则自动改成三角速度曲线，其峰值速度为：

```text
vpeak = sqrt(D × a)
```

默认参数 `vmax = 3 m/s`、`a = 2 m/s²` 时：

```text
ta = 3 / 2 = 1.5 s
da = 0.5 × 2 × 1.5² = 2.25 m
```

所以默认 `20 m` 的完整单程能够达到 `3 m/s`。

- 第一次从中心到 `+10 m`，距离只有 `10 m`，理论用时约 `4.83 s`；
- 后续从 `+10 m` 到 `-10 m`，单程 `20 m`，理论用时约 `8.17 s`；
- 正常的端点到端点再返回，理论周期约 `16.33 s`。

由于定时器离散步长、PX4 内环跟踪和仿真动力学，实测时间可能略有差异。

每段结束时程序把规划位置精确设在端点，并把速度、加速度都设为零，然后把下一段终点切换到另一侧。日志示例：

```text
Reached endpoint x=10.00; next endpoint x=-10.00
```

### 4.6 有限范围的保证

直线模式的位置由当前单程的解析轨迹直接计算，并在结束时钳定到端点。因此规划位置始终限制在：

```text
PX4 NED X: -10 m ～ +10 m
PX4 NED Y: 0 m
PX4 NED Z: -5 m
```

原参数 `max_range` 仍服务于原来的正弦、随机游走等模式，不负责限制新的直线模式。直线模式的范围由 `linear_path_length` 明确决定。

## 5. 为什么最初看起来是“朝相机前后飞”

这是本次修改中最容易混淆的一点：Gazebo 和 PX4 使用的坐标轴约定不同。

### 5.1 Gazebo ENU 与 PX4 NED 的对应关系

桥接代码采用以下转换：

```text
PX4 NED x = Gazebo ENU y
PX4 NED y = Gazebo ENU x
PX4 NED z = -Gazebo ENU z
```

可以理解为水平面的 `x`、`y` 在桥接时交换了。

两架无人机在 Gazebo 中的初始位置是：

```text
拦截机：PX4_GZ_MODEL_POSE="0,0"
目标机：PX4_GZ_MODEL_POSE="20,0"
```

这意味着目标机位于 Gazebo ENU 的 `+X` 方向；转换到目标机的 PX4 局部 NED 坐标后，拦截机到目标机的视线/前后方向与 NED `Y` 轴有关。

如果让目标机改变 PX4 NED `Y`，在拦截机相机中就容易表现成接近或远离，也就是“前后飞”。

### 5.2 最终修正

最终直线轨迹只改变 PX4 NED `X`：

```cpp
pos_x_ = linear_center_x_ + linear_position_;
pos_y_ = linear_center_y_;

publish_trajectory_setpoint(
    pos_x_, pos_y_, pos_z_,
    linear_velocity_, 0.0f, 0.0f,
    linear_acceleration_cmd_, 0.0f, 0.0f);
```

PX4 NED `X` 对应 Gazebo ENU `Y`，因此目标机会在两机初始连线的垂直方向运动，在拦截机视角中更接近横向经过。

## 7. 双机启动脚本摘要修正

文件：

```text
/home/ubuntu22/Autonomous-Intercept-Drone/run_swarm.sh
```

脚本真正用于生成目标机的命令一直是：



```text
Drone 2 位置 : (20, 0)
```

```text
sqrt((20 - 0)² + (0 - 0)²) = 20 m
```

```text
sqrt(20² + 1²) ≈ 20.02 m
```

实际距离以各自实时位置为准。

按原有流程启动拦截机控制与目标检测，让拦截机先起飞并进入搜索/等待状态。这样目标机开始横向运动时，检测链路已经工作。

### 11.1 提示 `Unknown motion_mode 'linear', defaulting to 'circle'`

原因：运行的是修改前的旧可执行文件。源码虽然已经改变，但实际工作空间没有重新编译，或者终端 source 了错误的 install 目录。

处理：

### 11.2 一直显示 `Waiting for stabilization`

先检查：

```bash
ros2 topic echo /px4_2/fmu/out/vehicle_local_position
```

重点看：

- `xy_valid`、`z_valid`、`v_xy_valid`、`v_z_valid` 是否为真；
- 实际位置是否接近 `(0, 0, -5)`；
- 三维速度是否能降到 `0.25 m/s` 以下。

如果仿真抖动确实略大，可在理解影响后临时放宽参数，例如：

```bash
-p staging_position_tolerance:=0.5 \
-p staging_velocity_tolerance:=0.35 \
-p staging_stable_duration:=0.5
```

放宽阈值会让目标机更早开始运动，因此不应在未查看实际状态前盲目调整。

### 11.3 日志显示 `max_range: 10.0m` 是否代表直线总长度只有 10 m

不是。`max_range` 是原有运动模式遗留的范围参数。新的直线模式使用 `linear_path_length=20.0`，两端点间总长度仍是 `20 m`。

### 11.4 为什么拦截机速度是 4 m/s，而目标机直线最大速度是 3 m/s

这是有意的实验设置。拦截机需要有一定速度优势才能逐步缩短距离。两者属于不同节点的参数：拦截机 `4 m/s` 是先前在启动命令中设置的；这里的 `linear_max_speed=3.0` 只控制目标机。

## 12. 如何切回圆周运动

原有圆周代码仍保留，因此临时切回圆周不需要回退源码或重新编译，只需要启动时覆盖参数：

```bash
ros2 run uav_target_sim uav_target_sim \
  --ros-args \
  -p motion_mode:=circle
```

或：

```bash
ros2 launch uav_target_sim target_sim.launch.py motion_mode:=circle
```

同理，仍可使用：

```text
motion_mode:=sinusoidal
motion_mode:=random_walk
```

## 13. 如何完整撤销本次源码改动

通常只需通过 `motion_mode:=circle` 切换实验模式，不建议为了临时做圆周实验而回退源码。

如果确实要把 4 个文件恢复到本次修改之前，可以在仓库中使用 Git。操作前先检查差异并保存当前成果，因为 `git restore` 会同时丢弃这些文件中此后尚未提交的其他修改：

```bash
cd /home/ubuntu22/Autonomous-Intercept-Drone

git diff -- \
  run_swarm.sh \
  uav_target_sim/include/uav_target_sim/uav_target_sim.hpp \
  uav_target_sim/src/uav_target_sim.cpp \
  uav_target_sim/launch/target_sim.launch.py
```

确认这些文件中没有需要保留的新修改后，才执行：

```bash
git restore -- \
  run_swarm.sh \
  uav_target_sim/include/uav_target_sim/uav_target_sim.hpp \
  uav_target_sim/src/uav_target_sim.cpp \
  uav_target_sim/launch/target_sim.launch.py
```

然后同步实际脚本并重新编译：

```bash
cp /home/ubuntu22/Autonomous-Intercept-Drone/run_swarm.sh \
   /home/ubuntu22/PX4-Autopilot/run_swarm.sh

cd /home/ubuntu22/autonomous_intercept_ws
source /opt/ros/humble/setup.bash
source /home/ubuntu22/ros2_px4_116_ws/install/local_setup.bash
colcon build --packages-select uav_target_sim --symlink-install
source /home/ubuntu22/autonomous_intercept_ws/install/setup.bash
```

更安全的长期做法是在验证成功后单独提交这 4 个文件。以后可以通过该提交查看、恢复或移植本次直线运动功能，而不会误伤相机频率等其他修改。
