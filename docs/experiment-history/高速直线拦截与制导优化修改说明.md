## 4. YOLO 置信度改为 0.70

文件：

```text
uav_vision_dectect/src/uav_topic_subscrib.cpp
```

当前存在两层门限。

检测器内部候选门限：

```cpp
config.confThreshold = 0.4f;
```

业务逻辑最终门限：

```cpp
if (has_valid_detection && best_score >= 0.70f)
```

调参过程为：

```text
约 0.80 -> 0.75 -> 0.70（当前值）
```

起飞后，目标像素尺寸、视角和机体姿态发生变化，置信度会从地面观察的约 `0.77` 降到 `0.70` 左右，因此最终采用 `0.70`。

同时加入节流调试日志：

```text
[YOLO DEBUG] candidates=... best_score=...
```

日志每 `500 ms` 最多打印一次，可以区分“YOLO 没有候选”和“有候选但没有超过业务门限”。

这是 C++ 修改，需要重新编译 `uav_vision_dectect`。当前安装的可执行文件最后构建于 `2026-11-16 17:11`。

## 5. PNG 参数调整

文件：

```text
uav_vision_png/config/params.yaml
```

### 5.1 `kz` 最终为 2.0

```yaml
kv: 4.0
kz: 2.0
```

`kz` 曾调为 `3.0`，并在目标 `6 m/s`、拦截 `8 m/s` 时得到过稳定成功结果。升到 `10/12 m/s` 后，水平响应过强容易使期望速度方向越过目标后方，因此最终降为 `2.0`。垂直增益 `kv` 仍为 `4.0`。

### 5.2 `d_gain` 最终为 1.8

调参过程：

```text
1.0 -> 1.6 -> 1.8（当前值）
```

对应代码：

```cpp
double d_v = Vt.norm() + d_gain_;
d_v = std::min(d_v, speed_cmd_);
```

`d_gain` 的作用是让下一次期望速度在当前三维速度模长上增加 `1.8 m/s`，再由 `speed_cmd` 截断。它会使加速更积极，但它**不是** PX4 的物理最大加速度，也不表示实际加速度固定为 `1.8 m/s²`。

### 5.3 `k1_yaw` 改为 0.00125

当前图像宽度为 `1280 px`，中心到边缘约 `640 px`。希望目标在画面边缘时产生约 `0.8 rad/s` 偏航角速度：

```text
k1_yaw = 0.8 / 640 = 0.00125
```

当前值：

```yaml
k1_yaw: 0.00125
k2_yaw: 0.0002
```

偏航指令仍限制在 `±1.0 rad/s`。修改目的是在高速追逐时更快让相机跟随目标，降低目标从视场横向滑出的概率。

## 6. 首次拦截连续 5 帧确认

相关文件：

```text
uav_vision_png/include/uav_vision_png/vision_png_control.hpp
uav_vision_png/src/vision_png_control.cpp
uav_vision_png/config/params.yaml
```

调参过程：

```text
单帧触发 -> 6 帧 -> 3 帧 -> 5 帧（当前值）
```

当前参数：

```yaml
detection_confirm_frames: 5
```

工作逻辑：

1. 拦截机起飞完成并进入 `SEARCHING`；
2. 每收到一帧有效检测，连续计数加一；
3. 任何一帧无效，计数立即清零；
4. 连续达到 5 帧后才进入 `INTERCEPT`；
5. 切换时重新初始化 PNG，并启动首次 LOS 角度限制。

日志示例：

```text
[LOCK] 连续有效检测 1/5
[LOCK] 连续有效检测 2/5
...
→ 连续检测确认，进入 INTERCEPT
```

这个确认只用于第一次 `SEARCHING -> INTERCEPT`。飞行中目标丢失后进入 `TRACK_LOST`，再次检测到目标会立即恢复拦截，不等待 5 帧，也不重复启用首次 15° 限制。

### 6.1 起飞完成条件

进入 `SEARCHING` 的条件同步改为：

```cpp
高度误差 < 0.5 m && |垂直速度| < 0.3 m/s
```

这样先确认拦截机已经接近待机高度且垂直运动基本稳定，再允许视觉触发拦截，避免起飞未稳时突然剧烈动作。

## 7. 期望速度方向与 LOS 的夹角限制

高速试验中，拦截机速度尚低时若立即使用大提前角，会把大量速度用于横向切入，闭合速度不足，甚至短时间内两机距离增大。为此加入两层限制。

### 7.1 按实际水平速度动态放宽

```yaml
los_limit_low_speed_mps: 8.0
los_limit_mid_speed_mps: 10.0
los_limit_low_angle_deg: 30.0
los_limit_mid_angle_deg: 45.0
max_velocity_los_angle_deg: 55.0
```

规则：

```text
水平速度 <= 8 m/s：最大夹角 30°
水平速度 8~10 m/s：30° 线性增加到 45°
水平速度 10 m/s~speed_cmd：45° 线性增加到 55°
```

当实验使用 `speed_cmd:=15.0` 时，高速插值区间就是 `10~15 m/s`。

限制的是：

```text
期望水平速度方向 - 当前目标 LOS 水平方向
```

不是机头与目标运动方向的夹角，也不是两条轨迹的几何夹角。

### 7.2 首次拦截 15°阶段

```yaml
initial_los_angle_deg: 15.0
initial_los_max_duration_s: 1.0
initial_los_exit_speed_mps: 8.0
initial_los_transition_duration_s: 0.4
```

第一次进入拦截后：

1. 最大 LOS 夹角先限制为 `15°`，优先直接接近目标；
2. 水平速度达到 `8 m/s`，或经过 `1.0 s`，满足任一条件便开始退出；
3. 用 `0.4 s` 从 `15°` 平滑过渡到常规动态限制；
4. 之后仅使用 `30°/45°/55°` 规则。

此阶段只在首次进入拦截时使用，飞行中重捕获不会重复启用。

### 7.3 防止越界角度在内部积累

限制完方位角后，程序执行：

```cpp
last_v_angle_z_ = d_v_angle_z_;
```

下一次 PNG 迭代从限制后的合法方向继续计算，不保留越界提前角。


这允许 PX4 接受最高约 `15 m/s` 的水平速度指令。它是启动时参数覆盖，不需要重新编译 PX4，重新执行脚本即可生效。

## 14. 当前已知注意事项

1. **两份 `run_swarm.sh` 不一致**：只有 PX4 实际脚本含 `MPC_XY_VEL_MAX=15`。
2. **高速值不是默认值**：必须继续显式写 `linear_path_length:=240.0`、`linear_max_speed:=10.0`、`speed_cmd:=15.0`。
